# gotzji — development and qualification

## Current source version: v1.0.0

Latest published release: **none**. The source is being developed toward gotzji v1.0.0. No official gotzji executable has been released. Historical lnwjud documentation is retained under docs/upstream/ and is not a description of gotzji's shipped features.

## App and jobs

The source now incorporates upstream lnwjud v5.8.7 at `1a0453ed0ef1de4cdf9ce1ba9edee8da0de8426b`, retaining gotzji identity, private storage and the existing job authority. The Tools reference covers all 294 upstream source definitions; this is separate from callable gotzji operations and installed/ChatGPT acceptance. Pinned upstream documents and the earlier 5.8.6 installed observations remain separately labelled under `docs/upstream/` and `docs/parity/`.

Start new work from ChatGPT. Desktop selects/configures projects, prepares copyable prompts, observes results and controls existing jobs. New-operation preparation and submission from Desktop are rejected by the host. Selecting a project starts no work and grants no additional access.

On a new chat, `gotzji_project_context()` returns the owner's selected project, current root instructions, saved conversation notes and the latest 25 canonical project jobs. Explicit `projectId` reads another enrolled project without changing selection. Use `gotzji_select_project(projectId)` to change the persistent owner selection across Desktop and ChatGPT. `gotzji_save_project_memory(projectId,expectedRevision,memory)` saves summary, decisions, open questions and result references with compare-and-swap conflict handling. These notes do not alter host policy, job status or proof of delivery; inspect full files/results when needed.

The desktop is a client of one independent local host. Closing the window does not transfer ownership or create another job engine. The host uses a native Goal ledger and stores request, operation, job, worker epoch, receipts and retained logs. ChatGPT controls typed mutations and durable workflows through the gotzji plugin; the app and ChatGPT inspect and cancel the same selected job. Project file reads execute directly in that host.

Use `gotzji_read_file(projectId,path)` for UTF-8 text up to 1 MiB and its exact SHA-256; `gotzji_list_files(projectId,path?)` for one directory; and `gotzji_search_files(projectId,path?,query)` for recursive case-sensitive literal search. These calls start no durable job or model provider. Text excludes NUL and binary control bytes (ordinary tab/newline/carriage return/form feed are allowed). Search queries are nonempty, single-line literals up to 1024 characters. Listings stop at 500 entries; searches stop at 100 matches, 10,000 scanned entries, 32 MiB of reads or a two-second processing budget. Listing/search responses stay within 64 KiB and report `truncated`, `incompleteReasons` and `skippedCount`; narrow the selected directory when coverage is incomplete. Redirected paths, multi-link files and private runtime/profile files are excluded. Legacy policy records are upgraded only from exact known bytes with the sealed authority and no admitted/uncertain work; edited policy is preserved and refused.

A project is registered locally. Model-visible tools cannot choose executables or enroll another owner. Reviewed command IDs resolve to server-owned executable, arguments and dependency hashes. Policies and file versions are checked before an effect. Writes preserve originals or create a backup. Conflicting project/document/provider resources wait; uncertain termination preserves its fence.

The owner's current ChatGPT account and conversation supply reasoning and call the plugin; the host executes supported typed operations directly. Beyond that ChatGPT account, normal operation requires no additional Claude, Grace, Codex, local/secondary inference backend, provider login, subscription, model or provider child process, and no paid inference API or second execution backend is introduced. Model-dependent Investment Library workflows are currently unsupported until an explicit ChatGPT orchestration and artifact-continuation contract preserves their analysis, specialist, audit, privacy, persistence and delivery obligations.

## Connections

The local app configures its own OpenAI Secure MCP Tunnel, independent of lnwjud. A dedicated runtime API key requires Tunnels Read + Use. Enter it in the app; never paste it into a chat or issue. The host protects credentials with Windows CurrentUser DPAPI. Tunnel transport uses authenticated loopback forwarding. Project enrollment and connection configuration are absent from ChatGPT's tool catalog.

The personal plugin requires actual Pro account/workspace consent and qualification; documentation or a local HTTP test does not accept the account. Intended Plus compatibility remains, but the owner's 2026-10-17 decision makes separate Plus qualification NOT_REQUIRED (G15), without asserting plan equivalence or a Plus PASS. Public ChatGPT directory submission is a separate later target.

### Session resilience / แนวทางสำหรับผู้ปฏิบัติการ

Use the selected job ID to inspect status, read bounded logs, retrieve a verified result, resume inspected work or cancel only that job. A closed app window or ChatGPT session does not own the worker. Reopen gotzji, select the same job and inspect its last progress before submitting anything again. If the host, provider or Windows session was interrupted, keep uncertain resources fenced until gotzji reports a verified effect or an action-required reason.

Connection and host listeners bind to loopback addresses with operating-system-assigned ports. Diagnostics and incident records are private, bounded and redacted; review them before sharing. A successful health response, observer exit or child command does not prove the workflow, artifact or delivery completed.
