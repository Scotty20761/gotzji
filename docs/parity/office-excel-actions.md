## Input and dispatch contracts

`office-tool-contracts.ts:60` owns the 85-action enum; `office-tool-contracts.ts:183` owns a strict common top-level input schema. Only `action` is required at that schema layer. Optional fields are `workspaceId,file_path,target_path,image_path,sheet,range,values,formulas,name,new_name,index,count,parameters,password,macro,dryRun,dry_run`. Path fields are nonempty strings up to4096; sheet/range/name/new_name up to256; password up to4096; macro up to512; index is a nonnegative integer, count a positive integer; `parameters` is an unknown-valued record. These are schema limits, not a promise that every action consumes every field.

`tools/upgrade-tools.ts:37` attaches the schema. `upgrade-tool-contracts.ts:317` routes semantic Office names to it; the output at `upgrade-tool-contracts.ts:324` is extensible `catchall(unknown)`, **not** a strict per-action output union. The action rows therefore record actual implementation returns rather than claiming a stronger output schema.

The three data workflows branch at `office-runtime.ts:157` before COM dispatch and require a registered `workspaceId` plus `file_path`. The 82 native actions pass supported-action checks, current read/mutation classification, default dry-run for mutations, application authorization and file-safety preparation, then `capabilities.execute('office',...)` at `office-runtime.ts:274`. Native success is wrapped at `office-runtime.ts:292` with `tool,status,available,ready,executed,dryRun,provider,app,action,result`. This inherited path is not the gotzji Core admission route and is not permission to enable raw legacy IPC.

Extended action `parameters` are strict at `office-tool-contracts.ts:433`; additional required top-level fields are checked at `office-tool-contracts.ts:493`. Base parameters often have only provider-side checks or casts. The table distinguishes explicit required/non-null checks from merely consumed/cast optional values; a consumed value is not silently promoted to a schema guarantee.
