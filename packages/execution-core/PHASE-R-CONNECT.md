1. Build `@gotzji/execution-core`, then run `node packages/execution-core/dist/phase-r-bootstrap.js --long` from the fork root. Keep the returned host config path local; its contents are private. Do not post it or the runtime key into a chat.
2. Open OpenAI Platform **Settings → Organization → Tunnels** (`https://platform.openai.com/settings/organization/tunnels`) in the same eligible personal context. A real new gotzji tunnel and runtime credential are required. Login/entitlement/permission issues must be resolved by the owner. Do not replace the existing lnwjud tunnel or invent its ID. The exact current credential-creation UI still requires live verification; no guessed click path is prescribed here.
3. In PowerShell, run the prepared helper with the actual new ID and exact host config:
   `& 'E:/Tools/gotzji/packages/execution-core/scripts/start-phase-r-tunnel.ps1' -TunnelId '<real new Tunnel ID>' -HostConfigPath '<private host config path>'`
   Enter the runtime key only into the hidden terminal prompt. The helper uses the official installed client, isolated gotzji profile, outbound connection and ephemeral loopback health port. It does not purchase/enable API inference or modify the original lnwjud profile.
4. In ChatGPT Plugins, create the personal app named **gotzji**, select **Tunnel**, enter that real ID, and use the tunnel's supported No Authentication MCP route (the local core still enforces private enrolled adapter/job authority). Review the discovered tools and native permission/consent prompt before the final connection. Security-sensitive access confirmation is handled at that actual step; source/development readiness is not consent evidence.

Inspect gotzji_job_status/validation_status while it runs; do not submit a new request after a lost response. When the same job reports completed, read gotzji_read_code_result. Report the actual job status, code result, artifact hash and run elapsed time. Do not call lnwjud or other filesystem/shell tools.
